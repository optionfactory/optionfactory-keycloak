# Changelog

## 9.18

- [FIX] online-access: the calling client's id was concatenated into the set of valid redirect uris, a copy of the block that collects authorized *clients*, where an id does belong. Realistic client ids never match a uri - `RedirectUtils` takes an entry literally unless it ends in `*` - so nothing was reachable through it, but the set now holds only the issuing client's redirect uris and those configured on the `online-access` role
- [FIX] email-sender: a malformed `allowed_cids.json` left the theme unable to send mail at all. The parse failure was wrapped in an `UncheckedIOException`, which sails past the sender's `catch (MessagingException | IOException)` and past the `EmailException` the spi declares, so a theme typo answered a password reset with a 500 - and re-parsed on every send, since a throwing loader caches nothing. It is logged and treated as an empty allowlist now: no cid is embedded until the file is fixed, and the mail goes out. Matching is also case insensitive on both sides, so an id written `Logo` in the template and `logo` in the allowlist no longer silently drops the image
- [FIX] providers, api-provisioning: a pass over the filtering and group plumbing. `GroupFilter` was the one filter that let a null through, where it binds as an untyped null inside `array[...]`; an offset/limit window with no sort ran over an unordered scan, so a row could come back on two pages or on none, and the user query now falls back to ordering by id when a caller asks for a window without saying how to sort it; `enforceServiceAccountHasClientRole` read only directly assigned roles, denying a service account that holds the role through a group or a realm composite; `Groups.provide` split paths with slash escaping always on while `Groups.search` followed the server setting, so a group created by path could not be found by the same path; and the recursive group-path CTEs had no `type` predicate, so with organizations enabled an organization's internal group surfaced as a realm group in a user's paths
- [FIX] online-access: the endpoints ignored `online-access--enabled`, which the readme has always described as enabling both halves of the feature. With the flag unset the action-token handler was null while the minting endpoint answered anyway, so the boot log said `disabled` while the api was live and the tokens it produced could not be redeemed. `create` now returns null when the flag is off, which is how keycloak's realm extension dispatcher answers 404, and minting and redeeming are switched together
- [FIX] providers, api-provisioning: malformed input on the filtering apis answered with a 500 where a 400 was meant. A sort expression of nothing but separators splits to no parts and was indexed anyway; an iso instant beyond what epoch milliseconds hold parses fine and overflows on conversion; an absent filter body, or a null value for a known filter, reached code that reads `values[0]` at once. A `limit` of `Integer.MAX_VALUE` on a slice overflowed to a negative fetch size, and the `id` filter on group membership was unqualified in a query that joins `user_entity`, so postgres called it ambiguous
- [FIX] authenticators: `opfa-verify-email-otp` replaced the stored code before it knew the mail had been accepted, so a transient smtp failure on a resend invalidated the code already sitting in the user's inbox and delivered nothing in its place - leaving them to wait out the cooldown. The code is stored once the send returns
- [FIX] authenticators: `conditional-user-group` compared the configured value against the group's *name*, while the console's group picker stores its *path* - so the condition never matched, silently disabling the gated sub-flow, or running it for everyone when negated. It resolves the path now, counts membership of any group below it (keycloak's own rule, via `RoleUtils.isMember`), and refuses to invert a condition it cannot answer: a group that no longer exists logs a warning and the sub-flow is skipped, rather than opening to everyone under `negate`
- [FIX] authenticators: `opfa-verify-email-otp` attached itself to users with no email at all, which upstream's `VerifyEmail` explicitly skips. The challenge ignores such users and only a success clears a required action, so the action pinned them as permanently pending - enough to make them unimpersonable, since `opfa-impersonation` refuses a target with obligations. The trigger now skips them and clears the action from the users it had already pinned
- [FIX] authenticators: `opfa-verify-email-otp` stored its code under the user alone, so an address that changed while a code was outstanding - an admin edit, a federation re-import, an idp mapper - could be marked verified by the code sent to the previous one, and the pending challenge asked for a code the new mailbox never received. The code is stored under the address it was sent to (hashed, the store is no place for addresses in clear), so a changed address gets a code of its own; the resend cooldown stays keyed by user, since it guards a mailbox from flooding
- [NEW] api-provisioning: `PUT`/`PATCH /provisioning/users` take an optional `password`, either as clear text (`{"value": "..."}`) or as a hash made elsewhere (`{"algorithm", "hashIterations", "hash"}`, plus `salt` where the algorithm keeps one apart from the hash - bcrypt and the like carry their own and send none), with exactly one of the two forms required. Clear text is hashed with the realm's algorithm and cost but deliberately not measured against the realm's password policy, so a migration can carry over a password the policy would refuse today; a hash is stored as it arrives and keycloak re-hashes it at the user's first login
- [FIX] api-provisioning: patching any attribute wiped the user's first name, last name and email. Keycloak reports those (and the username) among `getAttributes()`, so the default REPLACE patch listed them as removals, and removing a root attribute nulls the field itself
- [FIX] api-provisioning: `provide` ignored a changed `username` on an existing user, and defaulted a missing `enabled` or `emailVerified` to false - disabling an active user on a 204. Both flags are now required and reported when absent
- [FIX] api-provisioning: a rejected request committed whatever it had already written. A `BadRequestException` carrying an entity is returned by resteasy as it is and never reaches the error handler that marks the transaction for rollback, so the endpoints now mark it themselves
- [FIX] providers: `ResourceAuthenticator.enforceServiceAccountHasClientRole` authorized on the roles of the client's service account without checking who was calling, so any token issued to that client - a direct access grant for an ordinary user, say - passed a guard meant for the service account alone
- [FIX] idp-apple: the `user` form field, which the browser posts and nobody signs, overrode the email of the signature-verified id_token, and the address inherited its verified status. It is read for the name now, the one thing apple sends nowhere else
- [FIX] authenticators: the impersonation swap removed the cookie's user session and let the flow re-create one under the same id, in the same transaction, where the create discards the pending removal - committing a session whose stored user no longer matched. The session is handed to the target in place instead (`restartSession`, what `attachSession` itself uses for that case)

- [NEW] providers: `phonenumber`, a user profile validator backed by libphonenumber. Numbers in international `+CC` format always parse; national formats need `default-region` (an ISO 3166-1 alpha-2 code, checked against libphonenumber's supported regions), and `allowed-types` narrows the accepted `PhoneNumberType`s, defaulting to `MOBILE` and `FIXED_LINE_OR_MOBILE`. Blank values are skipped, so requiredness stays the user profile's business, and region and types are validated when the config is saved rather than when a user first hits the form. Its messages ship as `theme-resources/messages/`, the way the authenticators do, so every login theme resolves them and not just this project's; the libphonenumber jar is `provided` because the image stages it into `providers/`
- [FIX] api-provisioning: the inspection endpoints now tell a page and a slice apart. Only a slice fetches the row beyond the limit that answers "does another page follow", a page returns exactly the window asked for, and the arithmetic both share lives in `Window`. A page past the last one reported a total of zero, because `count(*) over()` yields no row when no row matches the offset - the total is now re-asked from the first page. An empty group built a `SliceResponse` and then returned a `PageResponse` regardless
- [FIX] api-provisioning: the recursive group-path CTE behind the user queries was not realm-scoped, so group names from other realms could surface in a user's path; its anchor now filters on `realm_id`. Lookup by username lowercases the needle, which is how keycloak stores usernames, keeping the `(realm_id, username)` index usable

## 9.17

- [NEW] authenticators: `opfa-impersonation`, a browser-flow authenticator (first `ALTERNATIVE`, bound to the target client) that swaps the operator's cookie-backed identity for a target user on `impersonate=<userId>` and restores it on `deimpersonate`: the operator comes from the identity cookie validated in-code, role-less or session-less attempts fall through to a normal login with an `IMPERSONATE_ERROR` event, targets are guarded (exists, enabled, not a service account, holders of the operator role are never impersonable, optional `forbiddenRole`, no pending required actions and a verified email, else a warning page with back navigation), the swap writes the native `IMPERSONATOR_ID`/`IMPERSONATOR_USERNAME` notes (built-in mappers and introspection `act.sub` for free) and removes the current session server-side (no orphans, no chained leftovers; an inline backchannel logout would delete the root authentication session the flow itself executes in, since the authorize endpoint re-creates it with the cookie user session's id), and `deimpersonate` re-validates the operator's role and enabled flag before restoring. Design and edge cases in `impersonation-spec.md`; the ambient-authority trade-off of a url-borne parameter is documented and accepted
- [NEW] authenticators: `opfa-verify-email-otp`, a required action replacing the built-in `VERIFY_EMAIL` where the magic link is a liability (mobile custom tabs: the link opens the default browser and the parked tab never resumes): the email carries a numeric code the user types into the still-open login tab. Codes are sha-256-hashed in the single-use object store, single-use, expire after `codeLifespanSeconds` (900), are invalidated after `maxAttempts` (5) failed submissions and resends are rate-limited by `resendCooldownSeconds` (30), with `codeLength` (6) rounding the config; a closed tab needs no recovery path, the action lives on the user so the next login re-prompts and accepts a still-valid code. The code protocol (hashed single-use codes in the single-use object store, attempts atomically claimed so the cap cannot be raced, putIfAbsent-claimed resend cooldown) is extracted into `otp.OtpCodes` for reuse by other one-time code flows
- [ENH] themes-preview: the gallery opens from the file system - `target/<output>/index.html` in a browser tab, no server. Module scripts are the one thing no browser loads from a `file://` origin, so they are rewritten as pages are generated: the import map goes (nothing is left to import), an importing script is dropped (the stock ones are behavioral - session polling, webauthn, passkeys - and a preview is a still), and a module-free one keeps running as a deferred classic script (the locale dropdown, the password toggle). The index's editor reaches its frames over `postMessage` - the one channel that crosses `file://` origins, where a parent cannot reach into them - through a listener injected into every page, which also blurs the page's own autofocus (the scroll guard the index used to do by hand, and cannot from `file://`); `localStorage` and the clipboard degrade instead of throwing where a `file://` origin refuses them. The `rfc4648` stub is gone with the modules that imported it, and `serve()` stays as a convenience for who prefers an url

## 9.14

- [ENH] themes-bootstrap: the card is tokenised - `--opfa-card-bg`, `-radius`, `-shadow`, `-max-width`, `-padding` and `-min-height`, all defaulting to today's stock look (transparent, square, 400px, 15px). - [ENH] themes-bootstrap: `.btn-secondary` and `.btn-outline-secondary` (`kcButtonDefaultClass`/`kcButtonSecondaryClass`) are driven by `--opfa-secondary{,-contrast,-border,-hover,-active,-disabled}`, the way `.btn-primary` already was - bootstrap compiles those palettes as literal hexes too, so every theme wanting a branded secondary was restating twelve `--bs-btn-*`. - [ENH] themes-bootstrap: `--bs-body-bg` and `--bs-body-color` now derive from `--opfa-surface-bg` and `--opfa-body-color`, so a theme tinting its fields no longer reaches for bootstrap variables directly; `--opfa-social-bg` defaults to the surface colour. They are declared under `:root:not([data-bs-theme="dark"])` rather than a bare `:root`, which would out-specify bootstrap's own dark block and pin the theme to light
- [BRK] themes-bootstrap: the action row sits at the bottom of a card taller than its content at any width, not only on a phone: the stretch chain leaves the library, so a theme that gives `.keycloak-card` a `min-height` gets its actions pinned on a desktop too, and a flow no longer resizes its box between steps. The chain makes those containers flex, which does not collapse margins, so the gap above an action row grows by the row's own `padding-top` where the block above it has a bottom margin - 32px instead of 16px on eight stock pages, up to 64px on `login-oauth-grant`. A theme that wants the old spacing sets its own `padding-top` on `#kc-form-buttons`/`.form-actions`
- [FIX] themes-bootstrap: the recovery-codes page reads as a page now: the warning is patternfly markup, so `kcRecoveryCodesWarning` drops `d-flex` (title above its description rather than beside it), the `pficon` box that resolves to nothing is hidden and the `h4` title is 1rem/600 instead of 1.5rem; the codes are monospace with a muted index (`kcRecoveryCodesList` gains a hook class); and the print/download/copy row has room around it and reads as accent-coloured links that underline on hover
