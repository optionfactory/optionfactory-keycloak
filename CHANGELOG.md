# Changelog

## 9.13

- [BRK] themes-bootstrap: `template.ftl` is a purely-additive fork of upstream 26.7.2 (stock macro signature): `header2`/`showTabs` sections, `bodyClass` rendering and the cards wrapper div are gone. Subtitles render in-form as `<p id="kc-page-subtitle">`, tabs move to page templates, `cards=true` ships its two-column layout (`left-card.ftl` include + per-page `footerCard` section), head tags reorder so `styles=` overrides bootstrap, and `meta=` properties replace hard-coded metas
- [BRK] themes-bootstrap: theming variables renamed to a single `--opfa-*` prefix, almost all of it derived: a theme setting only `--opfa-accent` gets the primary button, card border, checked checkbox and selected otp tile. `--theme-border-color`/`-background-color`/`-text-color` fold into `--bs-border-color`/`--bs-body-bg`/`--bs-body-color` (what bootstrap's own `.form-control` reads) and alert tints into `--bs-danger-{text-emphasis,bg-subtle,border-subtle}`, retinting `.alert-error` off the stale 5.2 palette; body/header/card backgrounds lose their no-op variables. The card top border defaults to `--opfa-accent`, matching the primary button the theme now themes at all. Was/now table in the module readme
- [BRK] themes-bootstrap: `theme.properties` maps all remaining `kc*Class` overrides (select-authenticator, otp tiles, recovery codes, webauthn icons, radio/checkbox groups, textarea, secondary/block buttons, social disabled state) and fixes the `kcLocaleListClass` misassignment. `kcButtonBlockClass` is `w-100 keycloak-button-block`: its `mt-2` is a library rule now, because a utility's `!important` could not be taken back off two block buttons sharing a line - move any `.mt-2` hook to `.keycloak-button-block`
- [BRK] themes-bootstrap: checkbox/radio geometry derives from `--opfa-checkbox-size` (default `1.25em`) and `--opfa-checkbox-gap`, for `.form-check` and the legacy `.checkbox` alike: bootstrap locks control, gutter and offset together, so a theme that only scaled the control got one hanging below its own line. A theme sizing checkboxes with a bare `input[type=checkbox]` rule should move to the token - the library's selector is (0,2,1) and now wins
- [BRK] themes-bootstrap: the `* required fields` hint (`.subtitle`) is styled by the library - right-aligned, 0.875em, `--bs-secondary-color`, on `span.subtitle` so the wrapper's own class cannot compound it. Derived themes can drop their rule; one that wants it hidden still needs `display: none`
- [NEW] themes-bootstrap: opt-in floating labels (`floatingLabels=true`, `css/keycloak-floating-labels.css`) with no javascript reparenting the dom: bootstrap's `.form-floating` wants control and label as direct siblings, control first, which keycloak emits in neither of its two markup shapes, so `:has()` on the `.form-group` reads the control's state instead. The flag also emits a parser-blocking one-liner giving every field the `placeholder` that `:placeholder-shown` needs. Geometry, colour and the float itself are `--opfa-floating-*` tokens
- [ENH] themes-bootstrap: bootstrap 5.3.2 -> 5.3.8, bootstrap-icons 1.11.2 -> 1.13.1 (CDN, SRI refreshed on both)
- [ENH] themes-bootstrap: tokens for what derived themes kept reimplementing - `--opfa-header-background`/`-header-text` (instead of hand-written `#kc-header-wrapper { display: none }`), `--opfa-body-bg` (tint inputs without tinting the page), `--opfa-card-border-color`, `--opfa-left-background`, `--opfa-font-family`/`-heading-color`, and `--opfa-primary{,-contrast,-border,-hover,-active,-disabled}` for the whole `.btn-primary` palette, which bootstrap compiles as literal hexes and every derived theme was restating in twelve `--bs-btn-*`. `kcHeaderWrapperClass` is gone: the library targets the stock `#kc-header-wrapper`
- [ENH] themes-bootstrap: css rewritten with nesting, dom order outer->inner, no `!important` and no specificity ladder - consumer sheets load last, so overriding is "copy the selector verbatim". The invalid state is one `.form-group:has([aria-invalid="true"])` block instead of four rules agreeing by hand, and the classless `.checkbox` upstream hardcodes is skinned to mirror `.form-check` exactly. `@layer` was rejected: bootstrap arrives unlayered from the CDN and unlayered declarations beat every layer. `kcFormButtonsWrapperClass=form-actions` retires the `#kc-form-buttons > div[class=""]` selector, `kcFormSocialAccountListButtonClass` sheds the utilities the css only overrode with `!important`, and dead rules are gone
- [ENH] themes-bootstrap: `select-organization` shares the social-provider skin (upstream builds it from the same `kcFormSocialAccount*` properties) and stops being pushed to the bottom of the card like an action row; the locale dropdown derives from `--opfa-accent` through two new derived tokens (`--opfa-accent-hover`, `--opfa-accent-subtle`), and the raised rows of both lists take their background from `--opfa-social-bg` (white by default) rather than a literal
- [FIX] themes-bootstrap: a pair of buttons rendered stacked on some pages, side by side on others, mid-card on two, and flush against the content on a desktop. Upstream builds an action row four ways and only two were styled, so the row is matched by shape rather than container name, keeps its row inside the mobile stretch chain, carries its own `margin-top` for a desktop and a `padding-top` the pinning auto-margin cannot eat, and claims no free space when it holds nothing but buttons. `flex-column` opts out; a container mixing fields in with its buttons gives them a line each
- [FIX] themes-bootstrap: three things upstream emits that no `kc*Class` reaches - a bare `kcCheckInputClass` checkbox with no wrapper (register's terms box, the recovery-codes confirmation), the recovery-codes print/download/copy buttons carrying patternfly classes only, and a stray `<hr>` in `login-password`'s field group - are skinned, laid out from the `--opfa-checkbox-*` tokens (floated like the wrapped flavours, so both sit on the first line and indent a second one identically), and hidden respectively
- [FIX] themes-bootstrap: undefined `--theme-border-color` broke the password-reveal border and its invalid state; the social heading targeted a removed `h4`; an invalid field lost its red border on plain `:focus` (a `<select>` focused by mouse matches `:focus`, not `:focus-visible`) and `<textarea>` was excluded from the field skin despite carrying `form-control`; selects were unstyled; the success icon was a sun; duplicate `max-width` in `.keycloak-card`; favicon 404 (the theme ships `img/favicon.ico`); select-authenticator's chevrons trailed each option's text because the fill div upstream puts before the arrow was mapped to no class (`kcSelectAuthListItemFillClass=flex-grow-1`)
- [NEW] themes-preview: new module rendering every stock base login page (auto-discovered from the keycloak-themes jar) through a login theme into an html gallery, doubling as a template/data-model compatibility smoke test. Naming the theme is the whole configuration - `preview().theme("mytheme").generate()` - because the chain (`parent=`), the message bundles, the locale, the theme's own step pages and the title all derive from it; `property(k, v)` previews a variant, `stepPages(...)` attaches a fixture, a `PreviewPlugin` shares a set of them, and `serve()` runs the gallery from a built-in http server (the frames carry module scripts, which no browser loads from `file://`) for a `@Disabled` test. The gallery index is an editor: it lists every custom property the linked stylesheets declare in a `:root` block, winner first with the overridden sheets collapsed, overrides them live in every frame together with arbitrary css, switches all frames between phone/tablet/desktop viewports, and hands the result back as css to paste into a stylesheet
- [FIX] themes-preview: `url.resourcesPath` was a bare `resources`, which is not a relative module specifier, so every `import` the stock templates build from it threw and no module in a previewed page ever ran (`authChecker`, the webauthn and passkey scripts); it is `./resources` now and all 47 pages load clean
- [FIX] themes-preview: provider-supplied `theme-resources` were ignored, so a derived theme's custom step pages previewed without their css/js and message bundle (several import `inputs.ftl` from there); `theme-resources/{resources,templates,messages}` are now picked up from every jar on the classpath with keycloak's precedence
- [ENH] themes: `opfa-freemarker-configurable` now expands `${conf.*}` in `theme.properties` values (properties, keyed resources, `themeHeaders`/`baseHeaders`) in addition to message bundles; `msg()`/`advancedMsg()` formatters are rebuilt over the expanded bundle (previously `${conf.*}` in messages reached `msg()` unexpanded and got mangled by the flat variable resolver); expansion semantics (verbatim unknown refs, `${k:fallback}`, `${k1,k2}` key chains, recursion) pinned by unit tests
- [BRK] remoting: `HttpClients` rebuilt as a builder (`trustSystem/trustCertificatesIn/trustAny`, `verifyHostnames/verifyHostnamesWith/verifyNoHostname`); the `HostnameOptions`-based `create` signatures are removed. the old `VERIFY` mode trusted any certificate chain while checking hostnames only; defaults are now fully verifying, with redirects/cookies/auth-caching off and opt-in
- [BRK] online-access: action-token login links are single-use again (the replay marker was invisible to keycloak's check since 26.6, making links replayable until expiry)
- [BRK] idp-apple: id-token signatures are validated via apple's jwks and the issuer is pinned; outbound access to `appleid.apple.com/auth/keys` is now required
- [FIX] api-provisioning: `groups/membership` query was syntactically invalid; boolean filters (`enabled`, `emailVerified`) never worked on postgres; blank usernames, negative offset/limit and group paths with blank segments returned 500s instead of 400s
- [FIX] email-sender: invalid `from`/`replyTo` addresses pass realm validation; recipients are now validated and idn-converted; duplicate cid references embedded one attachment per reference and duplicate allowlist ids broke all email sending
- [FIX] authenticators: sns client trusted any certificate and skipped hostname verification; conditional authenticators crashed on missing config
- [FIX] filtering: `sort=field,desc` sorted ascending; user input ending in a backslash escaped the appended like wildcard; case folding was locale-sensitive
- [FIX] login-stats: a malformed stored attribute crashed the listener on every login event of that user
- [ENH] email-sender: realigned with upstream `DefaultEmailSenderProvider` (26.7.2); smtp timeouts configurable, `envelopeFrom` via `mail.smtp.from`
- [ENH] idp-apple: pem-armored private keys tolerated; unparseable key material fails loudly instead of yielding a cryptic `invalid_client`
- [ENH] online-access: forged/unknown `alg` headers rejected with 403 instead of 500
- [NEW] test suite migrated to junit-jupiter (208 tests); remoting ships a raw-socket test http(s) server with deterministic failure injection
