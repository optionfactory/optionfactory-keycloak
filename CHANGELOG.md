# Changelog

## 9.13

- [FIX] themes-preview: provider-supplied `theme-resources` were ignored, so a derived theme's custom step pages previewed without their css/js, without their message bundle, and could not be rendered at all (several import `inputs.ftl` from there). `theme-resources/{resources,templates,messages}` are now picked up from every jar on the classpath with keycloak's precedence: the theme chain wins for templates and resources, its bundles overlay the provider ones
- [NEW] themes-preview: new module rendering every stock base login page (auto-discovered from the keycloak-themes jar) through a login theme into an html gallery (`target/theme-preview/`, ftl index); reusable by derived themes via a fluent builder — no subclassing (inheritance-chain hooks, per-page fixtures, `extraRender` for custom step pages); doubles as a template/data-model compatibility smoke test

- [ENH] themes-bootstrap: bootstrap bumped 5.3.2 → 5.3.8 and bootstrap-icons 1.11.2 → 1.13.1 (CDN, SRI refreshed, integrity now also pinned on the icons stylesheet)
- [BRK] themes-bootstrap: `template.ftl` is a purely-additive fork of upstream 26.7.2 (stock macro signature): `header2`/`showTabs` sections, `bodyClass` rendering and the cards wrapper div are gone. Subtitles render in-form as `<p id="kc-page-subtitle">` (collapsed when empty, kept above alerts); tabs moved to page templates; `cards=true` now ships its two-column layout in the library (`left-card.ftl` include + per-page `footerCard` section, no wrapper div); head tags reorder so `styles=` overrides bootstrap (googleFonts/baseHeaders first, `themeHeaders` last); `meta=` properties replace hard-coded metas
- [BRK] themes-bootstrap: `theme.properties` maps all remaining `kc*Class` overrides (select-authenticator, otp tiles, recovery codes, webauthn icons, radio/checkbox groups, textarea, secondary/block buttons, social disabled state); `kcLocaleListClass` misassignment fixed and a styled locale dropdown ships in css
- [BRK] themes-bootstrap: theming variables renamed to a single `--opfa-*` prefix. The surface is wider than the 20 declarations it replaces, but almost all of it derives: a theme that only sets `--opfa-accent` gets a matching primary button, card border, checked checkbox and selected otp tile for free. `--keycloak-*` is upstream's prefix — keycloak's own `keycloak.v2` theme declares five, including `--keycloak-card-top-color` for the same pixel this theme called `--keycloak-card-border-color`. `--theme-border-color`/`-background-color`/`-text-color` fold into `--bs-border-color`/`--bs-body-bg`/`--bs-body-color`, which is what bootstrap's own `.form-control` reads, so the input border and the reveal-button border are finally one value; alert tints fold into `--bs-danger-{text-emphasis,bg-subtle,border-subtle}` (retinting `.alert-error` from the stale bootstrap 5.2 palette `#842029`/`#f5c2c7` to 5.3's `#58151c`/`#f1aeb5`, matching the warning/info/success variants that already rendered 5.3 values). Body/header/card backgrounds lose their no-op variables — write plain css. The card top border now defaults to `--opfa-accent` (`#0066CC` → `#0d6efd`) so it matches the primary button, which the theme now themes at all (bootstrap compiles `.btn-primary` as literal hexes and reads `--bs-primary` nowhere, so a rebrand used to leave it blue). Full was/now table in the module readme
- [ENH] themes-bootstrap: tokens added for what derived themes actually kept reimplementing — `--opfa-header-background` plus `--opfa-header-text` (set it to `none` instead of hand-writing `#kc-header-wrapper { display: none }`, which all three in-house themes did), `--opfa-body-bg` (separate from `--bs-body-bg` so a theme can tint inputs without tinting the page), `--opfa-card-border-color` (defaults to `--opfa-accent`; every derived theme overrides it away from the accent), `--opfa-left-background`, and `--opfa-font-family`/`--opfa-heading-color`, which now drive `--bs-body-font-family`/`--bs-heading-color` so the whole surface is `--opfa-*`. `kcHeaderWrapperClass` is gone: the library targets the stock `#kc-header-wrapper` id instead
- [BRK] themes-bootstrap: checkbox/radio geometry is driven by `--opfa-checkbox-size` (default `1.25em`, up from bootstrap's `1em`) and `--opfa-checkbox-gap`. Bootstrap locks its control size, its `1.5em` gutter and its `.25em` top offset together, so a theme that only scaled the control got one hanging below its own line and overflowing the wrapper; all three now derive from the size, and the formulas reproduce bootstrap exactly at `1em`. Applied to `.form-check` and the legacy `.checkbox` alike, so the two stay identical at any size. A theme that sized checkboxes with a bare `input[type=checkbox]` rule should move to the token: the library's selector is (0,2,1) and now wins
- [ENH] themes-bootstrap: `.btn-primary` is driven by `--opfa-primary{,-contrast,-border,-hover,-active,-disabled}`, all defaulting off `--opfa-accent`. Bootstrap compiles that palette as literal hexes and reads `--bs-primary` nowhere, so every derived theme was restating all twelve `--bs-btn-*`; they now set two to five values instead. A theme wanting the derived shades sets nothing at all
- [BRK] themes-bootstrap: the `* required fields` hint (`.subtitle`, emitted by the stock template on `displayRequiredFields` pages) is now styled by the library — right-aligned, 0.875em, `--bs-secondary-color` — instead of inheriting body text at full size and left alignment. Size and colour go on `span.subtitle` because the wrapper div carries the same class and the two would otherwise compound. Derived themes that styled it themselves can drop their rule; one that wants it hidden still needs its own `display: none`
- [ENH] themes-bootstrap: `theme.properties` adds `kcFormButtonsWrapperClass=form-actions`, which retires the `#kc-form-buttons > div[class=""]` selector, and `kcFormSocialAccountListButtonClass` sheds the bootstrap utilities (`mb-2 border-0 rounded-0 border-bottom border-dark btn-social`) it was setting only for the css to override them with `!important`. The `keycloak-*` wrapper class names stay: they name no rule in this stylesheet, but their values are a dom contract that derived themes hook from their own css and javascript
- [FIX] themes-bootstrap: undefined `--theme-border-color` broke the password-reveal button border and its invalid state; social heading selector targeted removed `h4`; invalid border lost on hover/focus; selects unstyled next to inputs; success icon was a sun; duplicate `max-width` in `.keycloak-card`; favicon fallback 404 (theme now ships `img/favicon.ico`). Also: an invalid field lost its red border on plain `:focus` — a `<select>` focused by mouse matches `:focus` but not `:focus-visible`, so it went grey; `<textarea>` was excluded from the field skin by a `:where(input, select)` narrowing despite carrying `form-control` via `kcTextareaClass`, so textareas kept bootstrap's padding and blue focus ring; select-authenticator's chevrons trailed each option's text instead of lining up on the row's right edge, because the fill div upstream puts between the body and the arrow was mapped to no class and collapsed (`kcSelectAuthListItemFillClass=flex-grow-1`)
- [ENH] themes-bootstrap: css rewritten with nesting and restructured to follow the dom outer→inner, with the invalid state expressed exactly once — a single `.form-group:has([aria-invalid="true"])` block at (0,4,0) decides the field, the reveal button and the message together, replacing four scattered rules that had to agree by hand. No `!important` anywhere and no specificity ladder to learn: consumer sheets load last, so the rule is simply "copy the selector verbatim". `@layer` was considered and rejected — bootstrap arrives unlayered from the CDN and unlayered declarations beat every layer, so layering would forfeit the skin. The `.checkbox` wrapper upstream hardcodes around remember-me and logout-sessions (its input carries no class, so bootstrap cannot reach it) is skinned to mirror `.form-check`/`.form-check-input` exactly, glyph mechanism included, so the two flavours of checkbox are indistinguishable. Dead rules removed (`.invalid-tooltip`, a copy of `.form-check` byte-identical to bootstrap's own, two unreachable `:has()` guards, a never-computed `flex: 1`, the `name="cancel-aia"` stacking heuristic that fired on a single consumer page against the row default); paired buttons share a row by default (`flex-column` opts a page into stacking)
- [ENH] themes: `opfa-freemarker-configurable` now expands `${conf.*}` in `theme.properties` values (properties, keyed resources, `themeHeaders`/`baseHeaders`) in addition to message bundles; `msg()`/`advancedMsg()` formatters are rebuilt over the expanded bundle (previously `${conf.*}` in messages reached `msg()` unexpanded and got mangled by the flat variable resolver); expansion semantics (verbatim unknown refs, `${k:fallback}`, `${k1,k2}` key chains, recursion) pinned by unit tests
- [BRK] remoting: `HttpClients` rebuilt as a builder (`trustSystem/trustCertificatesIn/trustAny`, `verifyHostnames/verifyHostnamesWith/verifyNoHostname`); the `HostnameOptions`-based `create` signatures are removed. the old `VERIFY` mode trusted any certificate chain while checking hostnames only; defaults are now fully verifying, with redirects/cookies/auth-caching off and opt-in
- [BRK] online-access: action-token login links are single-use again (the replay marker was invisible to keycloak's check since 26.6, making links replayable until expiry)
- [BRK] idp-apple: id-token signatures are validated via apple's jwks and the issuer is pinned; outbound access to `appleid.apple.com/auth/keys` is now required
- [FIX] api-provisioning: `groups/membership` query was syntactically invalid; boolean filters (`enabled`, `emailVerified`) never worked on postgres; blank usernames, negative offset/limit and group paths with blank segments returned 500s instead of 400s
- [FIX] email-sender: invalid `from`/`replyTo` addresses pass realm validation; recipients are now validated and idn-converted; duplicate cid references embedded one attachment per reference and duplicate allowlist ids broke all email sending
- [FIX] authenticators: sns client trusted any certificate and skipped hostname verification; conditional authenticators crashed on missing config
- [FIX] filtering: `sort=field,desc` sorted ascending; user input ending in a backslash escaped the appended like wildcard; case folding was locale-sensitive
- [FIX] login-stats: a malformed stored attribute crashed the listener on every login event of that user
- [ENH] email-sender: realigned with upstream `DefaultEmailSenderProvider` (26.7.2); smtp timeouts configurable, `envelopeFrom` via `mail.smtp.from`
- [ENH] idp-apple: pem-armored private keys tolerated; unparseable key material fails loudly instead of yielding a cryptic `invalid_client`
- [ENH] online-access: forged/unknown `alg` headers rejected with 403 instead of 500
- [ENH] themes: `opfa-freemarker-configurable` now expands `${conf.*}` in `theme.properties` values (properties, keyed resources, `themeHeaders`/`baseHeaders`) in addition to message bundles; `msg()`/`advancedMsg()` formatters are rebuilt over the expanded bundle (previously `${conf.*}` in messages reached `msg()` unexpanded and got mangled by the flat variable resolver); expansion semantics (verbatim unknown refs, `${k:fallback}`, `${k1,k2}` key chains, recursion) pinned by unit tests
- [NEW] test suite migrated to junit-jupiter (208 tests); remoting ships a raw-socket test http(s) server with deterministic failure injection
